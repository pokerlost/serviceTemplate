# Create and update a Pokerlost service

Read `AGENTS.md`, [TEMPLATE.md](TEMPLATE.md), and [SDK_COMPATIBILITY.md](SDK_COMPATIBILITY.md) before generation. The active Copier source is the root `copier.yml` with `composedTemplate/`.

## 🚀 Fresh copy

```bash
uv run --no-project --with 'copier==9.17.2' copier copy \
  --vcs-ref=<reviewed-service-template-commit> /path/to/serviceTemplate \
  /path/to/newService -d service_name=newService
cd /path/to/newService
uv lock
uv sync --locked
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked mypy
uv build --no-build-isolation
uv run --locked uvicorn newservice.app:create_app --factory --host 127.0.0.1 --port 8000
```

The private SDK is pinned by full Git commit in `foundationOverlay/pyproject.toml.jinja`. Local lock/install uses normal Git SSH read access; the SDK remains an installed runtime dependency. Never copy a key or source checkout into the generated app. The default needs no `.env` or database. `SERVICE.md` and `PROJECT.md` must be replaced with actual service boundaries before product behavior. Technical tests, source CI, and a backend Dockerfile are generated by default. Private SDK build access uses the existing SDK-only App with Contents: read on
pypokerlost. The approved consumers already hold the required repository secrets; never copy
a key into source, commands or artifacts. The [admission policy](.github/docs/sdk-admission.md)
binds a trusted default workflow and a separately reviewed full source SHA, with fresh owner
writer review. This is the approved sole-owner policy, not independent environment approval.
An ordinary source-only PR check does not prove an installed wheel or image.

The backend Dockerfile uses Python 3.14 and a BuildKit secret mount named sdk_token only during
locked dependency installation. The reviewed workflow supplies a short-lived SDK-only token;
no token is a build argument or image layer. Source, installed package, readiness, Alembic and
Kind checks execute after cache restoration. See [operation naming](docs/operationNaming.md)
for external IDs, Python names and the infrastructure exceptions.

## 🔁 Reviewed update

Update the parent Python source, refresh the FastAPI snapshot and derivative, then refresh this template's FastAPI snapshot and derivative. Record content SHA-256 provenance at each step. Review answer migration (`service_name` to derived Python names), managed paths, optional persistence, and SDK compatibility. A dirty local template is a worktree snapshot, not a release. The three-layer propagation and historical flat-source update were verified with actual local Git refs in disposable repositories. Select the actual reviewed commit with `git rev-parse HEAD`; neither a content hash nor an unreleased template version is a Copier Git ref.

In an existing service, preserve `SERVICE.md`, `PROJECT.md`, code, scopes, settings, and migrations. Back up dirty tracked and required untracked content before update. Commit a reviewed foundation baseline where authorized, rehearse the update on an isolated copy, then run `copier update` from the service root with the reviewed template commit. Inspect every `UU` conflict and proposed deletion, then port intended flat-layout code explicitly. For an existing database-backed service, pass `-d withPersistence=true`; the new default is false. The [migration guide](docs/migrationGuide.md) records the verified behavior and recovery boundary. Do not alter live DB revisions or use a template update as a schema downgrade.

Use a disposable render for HTTP/lifespan checks. `GET /` must use `PokerlostResponse[None]`, `GET /getOpenApi` must return the actual OpenAPI document, and no protected or business route exists in a pristine service. Run the generated suite with `uv run --locked pytest`. A positive DB readiness check requires a disposable PostgreSQL instance.

## 🧪 Technical verification

Run `make test-unit` for isolated coverage and `make test` for every enabled capability. A DB render
requires `TEST_DATABASE_URL` to identify a disposable PostgreSQL database. Integration proves real
commit/rollback and readiness, with no dependency substitution. `TestClient` is used as a context
manager so startup/shutdown run; the async PostgreSQL test keeps lifespan and HTTPX requests in one
event loop. Only deliberate HTTP 500 assertions disable server exception propagation.

The canonical container commands are `make build image test-image`. For the private dependency,
pass `DOCKER_BUILD_ARGS='--secret id=sdk_token,env=SDK_APP_TOKEN'` only in a reviewed environment
with a short-lived SDK-only read token. The token is a BuildKit secret mount, never a build argument
or copied file. `make chart` packages the inherited chart. `make deploy-local` creates its own Kind
cluster and kubeconfig; `make undeploy-local` deletes only that local contour. External deployment
requires an explicit approved target and registry manifest digest.
