# PokerLost Service Template

## Purpose

`serviceTemplate` is the reusable Copier baseline for PokerLost backend services. It generates
infrastructure and general architectural primitives, never a concrete service domain.

## Generation model

Copier asks for one value:

```text
service_name
```

It is the canonical camelCase or PascalCase service identity, for example `authService`,
`virtualMoney`, or `PokerServer`.

Copier derives, rather than asks for:

```text
service_slug
service_env_prefix
database_name
```

For example:

```text
service_name       = virtualMoney
service_slug       = virtualmoney
service_env_prefix = VIRTUALMONEY
database_name      = virtualmoney
```

## Generated service documents

Every generated service receives `AGENTS.md` and `SERVICE.md`.

- `AGENTS.md` contains shared PokerLost engineering conventions.
- `SERVICE.md` is the living service-owned description of purpose, responsibilities, and
  service-specific rules.

Agents working in a generated service read both files before changing it. Copier preserves an
existing `SERVICE.md` during updates.

## Base stack

Every generated service includes:

```text
FastAPI
Pydantic v2
Pydantic Settings
PostgreSQL
SQLAlchemy 2
Alembic
request-owned transaction
Logfire foundation
Gunicorn + Uvicorn worker
Typer CLI
Docker
Helm
uv
Ruff
mypy

```

PostgreSQL is an unconditional part of the base stack.

## Base architecture

The generated scaffold separates:

```text
app/api
app/application
app/configuration
app/domain
app/observability
app/persistence
app/cli
alembic
deploy/helm
```

The application layer provides only abstract `Command`, `Query`, `Result`, and `Handler`
primitives. Persistence provides reusable SQLAlchemy, repository, result-reader, and projection
foundations without a concrete business table or migration.

## API rules

- `GET /` is the only non-RPC application path.
- Other service endpoints use `/{namespace}.{method}`.
- Every endpoint and handled error uses `ApplicationResponse`.
- Application-owned JSON fields use `snake_case`.
- Request classes use `SomethingRequest` in `something_request.py`.
- Response classes use `SomethingResponse` in `something_response.py`.
- ORM-backed API schemas are responses and also end in `Response`.
- FastAPI dependencies are consumed through PEP 695 aliases; resolver functions remain private.
- OpenAPI is generated by FastAPI and receives only minimal PokerLost metadata.
- Built-in `/openapi.json`, `/docs`, and `/redoc` are disabled; the wrapped document is available
  through `GET /openapi.get`.

## Persistence rules

- One HTTP request owns one `AsyncSession` and one transaction.
- Successful dependency exit commits; an exception rolls back; exit closes the session.
- Routes, handlers, repositories, and query adapters do not call `begin()`, `commit()`, or
  `rollback()`.
- Concrete ORM classes use `SomethingModel` in `something_model.py`.
- SQLAlchemy 2 typed declarative mappings and explicit statements are preferred.
- Read projections remain separate from ORM models and API responses.
- Alembic uses common metadata and starts without a fake revision.

## Intentionally absent

The template does not implement users, accounts, roles, an authorization server, JWT/JWKS,
sessions, credentials, wallets, holds, a ledger, poker tables, blockchain integration, an OpenAPI
registry, durable audit, business rate-limiting policy, or any other service-specific behavior.

## Ownership

Copier owns and evolves the reusable scaffold. After initial generation, the concrete service owns
its `SERVICE.md` and all business/domain implementation added for its explicitly known
responsibilities. Template documentation never invents those responsibilities.
